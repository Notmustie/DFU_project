# Validity of Color-Derived Severity Labels for Diabetic Foot Ulcers: A Methodological Study

**Authors:** Mustapha Nasser, MD Iftekharul Mobin, Mahamodul Hasan Mahdi

**Corresponding author:** MD Iftekharul Mobin (iftekhar.mobin@aiub.edu)

**Affiliations:** Department of Computer Science, American International University-Bangladesh (AIUB), Dhaka, Bangladesh; Department of Computer Science and Engineering, Bangladesh University of Engineering and Technology, Dhaka, Bangladesh (M. H. Mahdi)

**Status:** manuscript submitted to *Health Science Reports* (under review).
**Archived release:** [Zenodo DOI(https://doi.org/10.5281/zenodo.23335668)]

---

This repository contains the research pipeline, derived labels, result files and
verification materials for a study on deriving and validating severity labels for
diabetic foot ulcer (DFU) images.

The central finding is a validated negative result: color-based tissue proportion
analysis does not recover clinical severity, and the failure is identifiable rather
than incidental. A control experiment on the DFUC 2024 infection task (AUROC 0.812
under the identical pipeline) shows that the failure lies in label provenance, not
model capacity.

## Running the pipeline

### Requirements

```bash
pip install -r requirements.txt
```

Python 3.10+. A GPU is strongly recommended for notebooks 05, 07b and 08.
Notebooks 05 and 07b have Colab companions (`*_colab.ipynb`) for T4 execution.

### Notebook order

Each notebook asserts its inputs and writes outputs consumed by the next.
Run them in sequence:

| Notebook | What it does | Heavy compute? |
|---|---|---|
| `01_deduplication` | Content-hash identity resolution | No |
| `02_label_derivation` | k-means tissue proportions + threshold labels | No |
| `03_label_validation` | Four validation checks | No |
| `04_split` | Patient-grouped 5-fold splits, leakage checks | No |
| `05_feature_extraction` | Frozen backbone features (.npy) | **Yes, use Colab** |
| `06_severity_models` | Six-configuration severity ablation | ~5 min CPU |
| `07_infection_control` | Control experiment, infection task | ~5 min CPU |
| `07b_finetune` | Full backbone fine-tuning | **Yes, use Colab** |
| `08_gradcam` | Grad-CAM on held-out images | ~10 min GPU |
| `09_statistics` | Bootstrap CIs, paired tests, Holm correction | No |
| `10_figures` | Regenerate all paper figures | No |

### Setting paths

Open **Cell 1** of any notebook. Set `PROJECT_ROOT` to your local project
directory. Every image path comes from the CSVs generated during deduplication,
so nothing else needs manual editing.

### Colab workflow (notebooks 05 and 07b)

1. Run `make_images_zip.py` locally after notebooks 01-04:
   ```bash
   python make_images_zip.py
   ```
2. Upload `images.zip`, the fold CSVs, and the Colab notebook to Google Drive.
3. Open the `*_colab.ipynb` in Colab, set `DRIVE` in Cell 2, and run top to bottom.

Random seed: 42. Cross-validation: five-fold, patient-grouped.

## Verifying the paper's claims

Open `notebooks/verification_notebook.ipynb`. The notebook detects which
verification level is available and tells you at startup.

### Level 1: results only (runs anywhere, ~30 seconds)

Requires only the `results/` folder already in this repo. No images or feature
arrays needed. Loads cached JSONs, recomputes bootstrap CIs and paired t-tests,
checks every paper claim against the stored values, and exports
`verification_log.csv`.

**This is the minimum required to reproduce the statistical claims in the paper.**

### Level 2: with feature spot-checks (~1-2 minutes)

Requires the cached feature arrays from notebook 05. Trains a fresh
one-configuration model on two held-out folds, confirms that the training code
executes and lands near the cached result, and renders confusion matrices.
The cached five-fold table (Level 1) is the primary claim; this step shows that
the code is not just loading a number.

To generate features, run notebook 05 (or its Colab companion) once.

### Level 3: full live reproduction (requires images)

Requires the wound images downloaded from the sources above. Runs the label
derivation on real photographs, shows the negative control on real healthy-skin
images, renders the stability comparison, and computes Grad-CAM heatmaps using
your trained checkpoint from notebook 08.

## Key findings

| Check | Result |
|---|---|
| Expert agreement (derived vs reviewer A) | κ = −0.025 |
| Expert agreement (derived vs reviewer B) | κ = +0.036 |
| Inter-rater agreement (A vs B) | κ = 0.254 |
| Negative control (lesion-free skin graded severe) | 60.2% (327/543) |
| Stability (photographs with >1 grade across augmented copies) | 61.7% (1,739/2,818) |
| Control task AUROC (expert infection labels, same pipeline) | 0.8123 (95% CI 0.796–0.833) |
| Fine-tuning vs frozen probe (AUROC) | +0.0057 (0.8180 vs 0.8123) |
| Gate scalar γ across folds | mean +0.090, SD 0.901, P = .852 vs zero |
| Gated model vs CNN baseline (AUROC change) | −0.0169, Holm-adjusted P = .003 |

All numbers in the paper trace to a specific cell in `verification_notebook.ipynb`.

## TGO-Net (Tissue-Guided Ordinal Network)

A custom architecture introduced in this study. Three components:

- **Tissue Proportion Encoder:** 3 → 32 → 64, GELU, LayerNorm. 2,432 parameters.
- **Cross-Modal Gate:** per-channel multiplicative fusion with a single scalar γ
  initialized at zero. The model starts as a pure CNN baseline; the tissue pathway
  must earn any influence. 83,201 parameters.
- **Prediction head:** CORAL (ordinal, severity task) or binary logit (infection task).

Total trainable: 86,915 parameters, 1.62% of the frozen EfficientNet-B0 backbone.

The gate scalar is a readable diagnostic of modality reliance. On derived labels the
model appears to perform very well because the tissue proportions are the
label-generating variable (circularity). On expert infection labels the gate scalar
is indistinguishable from zero (P = .852) and the gated model is slightly worse than
the CNN baseline.
