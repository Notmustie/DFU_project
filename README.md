# The Label Provenance Problem in DFU Severity Grading
## Validating Tissue-Derived Labels, Leakage-Free Evaluation, and Tissue-Mapped Explainability

**Author:** Mustapha Nasser (ID 211002042)
**Institution:** American International University Bangladesh (AIUB)
**Course:** CSC 5210

---

This repository contains the full research pipeline, paper, and verification
materials for a study on deriving and validating severity labels for diabetic
foot ulcer (DFU) images.

The central finding is a validated negative result: colour-based tissue
proportion analysis does not recover clinical severity, and the failure is
identifiable rather than incidental. A control experiment on the DFUC 2024
infection task (AUROC 0.81 under the identical pipeline) establishes that the
failure lies in label provenance, not model capacity.

## Running the pipeline

### Requirements

```bash
pip install -r requirements.txt
```

Python 3.10+. GPU strongly recommended for notebooks 05, 07b, 08.
Notebooks 05 and 07b have Colab companions (`*_colab.ipynb`) for T4 execution.

### Notebook order

Each notebook asserts its inputs and writes outputs consumed by the next.
Run them in sequence:

| Notebook | What it does | Heavy compute? |
|---|---|---|
| `01_deduplication` | Content-hash identity resolution | No |
| `02_label_derivation` | k-means tissue proportions + threshold labels | No |
| `03_label_validation` | Four validation checks | No |
| `04_split` | Patient-grouped 5-fold splits, zero leakage | No |
| `05_feature_extraction` | Frozen backbone features (.npy) | **Yes — use Colab** |
| `06_severity_models` | Six-config severity ablation | ~5 min CPU |
| `07_infection_control` | Control experiment — infection task | ~5 min CPU |
| `07b_finetune` | Full backbone fine-tuning | **Yes — use Colab** |
| `08_gradcam` | Grad-CAM on held-out images | ~10 min GPU |
| `09_statistics` | Bootstrap CIs, paired tests, Holm correction | No |
| `10_figures` | Regenerate all paper figures | No |

### Setting paths

Open **Cell 1** of any notebook. Set `PROJECT_ROOT` to your local project
directory. Every image path comes from the CSVs generated during deduplication,
so nothing else needs manual editing.

### Colab workflow (notebooks 05 and 07b)

1. Run `make_images_zip.py` locally after notebooks 01-04:
   ```bash
   python make_images_zip.py
   ```
2. Upload `images.zip`, the fold CSVs, and the Colab notebook to Google Drive.
3. Open the `*_colab.ipynb` in Colab, set `DRIVE` in Cell 2, and run top to bottom.

## Verifying the paper's claims

Open `notebooks/verification_notebook.ipynb`. The notebook automatically
detects which verification level is available and tells you at startup.

### Level 1 — results only (runs anywhere, ~30 seconds)

Requires only the `results/` folder already in this repo. No images or
feature arrays needed. Loads cached JSONs, recomputes bootstrap CIs and
paired t-tests, checks every paper claim against the stored values, and
exports `verification_log.csv`.

**This is the minimum required to reproduce the statistical claims in the paper.**

### Level 2 — with feature spot-checks (~1-2 minutes)

Requires the cached feature arrays from notebook 05. Trains a fresh
one-configuration model on two held-out folds live, confirms the training
code executes and lands near the cached result, and renders confusion matrices.
The cached five-fold table (Level 1) is the primary claim; this cell proves
the code is not just loading a number.

To generate features: run notebook 05 (or its Colab companion) once.

### Level 3 — full live reproduction (requires images)

Requires the wound images downloaded from the sources above. Runs the
label derivation live on real photographs, shows the negative control on
real healthy-skin images, renders the stability comparison, and computes
Grad-CAM heatmaps using your trained checkpoint from notebook 08.

## Key findings

| Check | Result |
|---|---|
| Expert agreement (derived vs reviewer A) | κ = −0.025 |
| Expert agreement (derived vs reviewer B) | κ = +0.036 |
| Inter-rater agreement (A vs B) | κ = 0.254 |
| Negative control (healthy skin → severe) | 60.2% |
| Stability (photographs with >1 grade) | 61.7% |
| Control task AUROC (expert labels, same pipeline) | 0.810 (95% CI 0.797–0.829) |
| Fine-tuning delta vs frozen probe | +0.008 |
| Gate scalar p-value vs zero | 0.90 (not significant) |

All numbers in the paper trace to a specific cell in `verification_notebook.ipynb`.

## TGO-Net (Tissue-Guided Ordinal Network)

A custom architecture introduced in this study. Three components:

- **Tissue Proportion Encoder** — 3 → 32 → 64, GELU, LayerNorm. 2,432 parameters.
- **Cross-Modal Gate** — per-channel multiplicative fusion with a single scalar γ
  initialised at zero. The model starts as a pure CNN baseline; the tissue pathway
  must earn any influence. 83,201 parameters.
- **Prediction head** — CORAL (ordinal, severity task) or binary logit (infection task).

Total trainable: 86,915 parameters = 1.62% of the frozen EfficientNet-B0 backbone.

The gate scalar is a readable diagnostic of modality reliance. On derived labels it
appears high because the tissue proportions are the label-generating variable
(circularity). On expert infection labels it is indistinguishable from zero (p = 0.90)
and the gated model is slightly worse than the CNN baseline.
